Each change adds one file under `unreleased/<section>/`, named `<yyyymmdd>-<slug>.md` so entries sort by date, holding one `- **Lead.** Detail.` entry. The sections are `added`, `security`, `changed`, `removed`, `fixed` and `internal`. CHANGELOG.md is generated from these files by `scripts/changelog.py` (`just changelog`), so it is never edited by hand. When `MARKETING_VERSION` is raised for a release, `just changelog --release X.Y.Z` turns `unreleased/` into that version. Releases before fragments were adopted keep their text as each version's `_intro.md`. A pull request adds its fragment and leaves CHANGELOG.md alone; the release PR (`just release`) is what regenerates it, so two open pull requests never conflict on it. The notes shown to TestFlight testers and on Play are assembled from the fragments, not read from the file.
