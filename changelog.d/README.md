Each change adds one file under `unreleased/<section>/`, named `<yyyymmdd>-<slug>.md` so entries sort by date, holding one `- **Lead.** Detail.` entry. The sections are `added`, `security`, `changed`, `removed`, `fixed` and `internal`. CHANGELOG.md is generated from these files by `scripts/changelog.py` (`just changelog`), so it is never edited by hand. When `MARKETING_VERSION` is raised for a release, `just changelog --release X.Y.Z` turns `unreleased/` into that version. Releases before fragments were adopted keep their text as each version's `_intro.md`.
